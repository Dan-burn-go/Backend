# 011. 혼잡도 이력은 @Async 로 저장하고 7일만 보관한다

- 날짜: PRD v1.4 (2026-04-03) 이전
- 상태: 채택

## 배경
5분 주기로 122개 장소를 수집한다. 수집 경로에서 MySQL 쓰기를 동기로 하면 외부 API 응답 지연과 DB 쓰기 지연이 한 주기 안에서 겹친다. 이력을 무한 보관하면 디스크도 계속 늘어난다.

## 결정
- 실시간 조회는 Redis(15분 TTL)가 받고, MySQL 이력 저장은 `@Async` 백그라운드로 보낸다
- 이력은 7일만 보관하고 매일 03:00 크론으로 초과분을 삭제한다

## 근거
- 조회 경로와 저장 경로를 분리하면 수집 주기가 DB 쓰기 속도에 묶이지 않는다
- 제공 기능(24시간 추이, 요일별 평균)에 7일이면 충분하다
- 정리 작업은 예외를 흡수해 다음 주기를 지킨다 (`DataCleanupSchedulerTest.cleanupOldData_exception`)

## 결과/영향
- 수집 직후 MySQL 에 아직 없을 수 있다. 조회는 Redis 우선이라 사용자 영향은 없지만, 이력 기반 통계는 약간 늦게 반영된다
- 7일을 넘는 기간의 통계는 낼 수 없다. 더 긴 추이가 필요하면 보관 정책을 다시 정해야 한다
- 운영 디스크가 빡빡한 환경에서 이 정책이 디스크 증가를 억제하는 역할도 한다 (`../failures/001-disk-full-outage.md`)
