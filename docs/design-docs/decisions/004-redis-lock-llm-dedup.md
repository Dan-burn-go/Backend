# 004. Redis 분산락으로 중복 LLM 요청을 막는다 (요청 멱등성)

- 날짜: 2026-07-06
- 상태: 채택

## 배경
같은 장소·같은 시점의 혼잡 이벤트가 중복으로 들어오면 같은 분석을 LLM 에 두 번 이상 요청한다. 토큰이 그만큼 더 나가고, 같은 리포트가 중복 저장될 여지도 생긴다. 소비자를 여러 개 띄우면 프로세스 안의 락으로는 막을 수 없다.

## 결정
Redis 분산락으로 요청 멱등성을 보장한다. 동일 키의 분석이 이미 진행 중이면 뒤에 온 요청은 LLM 을 호출하지 않는다.

## 근거
- 토큰 비용이 호출 횟수에 바로 비례하고, 외부 API 는 호출 제한이 있다
- 소비자 수평 확장과 양립해야 해서 프로세스 로컬 락은 선택지가 아니었다
- Redis 는 이미 캐시·폴백 용도로 쓰고 있어 새 인프라가 늘지 않는다
- 중복 억제 동작은 부하 테스트로 확인했다 (`load-test/`, 커밋 `c2c7585`)

## 결과/영향
- 락 만료 시간이 분석 소요보다 짧으면 중복이 다시 생긴다. 분석 시간이 길어지면 같이 조정해야 한다
- Redis 장애 시 중복 억제가 사라진다. 분석 자체는 계속된다
